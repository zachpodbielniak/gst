* Scope and method

Reviewed GST on =master= starting from =307de2b9cf9b2477dc33278338bad927b6fbdf1e=. Preserved the earlier agent's nine modified test files and three new test files, validated their assertions individually, and extended the regression coverage. No dependency source was inspected or edited. Normal project builds compiled their required dependencies; existing graylib/raylib archives were linked for LRG verification.

The first suite run stopped individual binaries at their first assertion failure. Running each registered test separately exposed 23 failing cases in the inherited suite. Further regression tests were added for integer boundaries, escape cancellation, reset state, selection release, sixel parameters, external pipes, build integration, and Webview. Every finding below has an observed failing assertion, crash, sanitizer report, or build failure before its fix. Multiple test cases can exercise one root cause.

* Verification

** Build packages

Required Fedora packages: =gcc make pkgconf-pkg-config glib2-devel libX11-devel libXft-devel libXrender-devel fontconfig-devel libyaml-devel json-glib-devel=. Wayland adds =wayland-devel libxkbcommon-devel cairo-devel libdecor-devel=. MCP/Webview add =libsoup3-devel libdex-devel libpng-devel=. LRG adds =mesa-libGL-devel= and uses the existing vendored archives. No packages were installed and no host overlay was enabled.

** Release build

A fresh output directory was used to force a complete GST build without invoking clean recipes that remove generated dependency headers. The final full-option suite passes 254 test cases, including MCP and Webview; there are no compiler warnings in either the fresh build log or the final verification log.

#+begin_src bash
make -j8 BUILDDIR=build/review-final MCP=1 WEBVIEW=1 LRG_BACKEND=1 all tests
#+end_src

The initial fresh build found a mistake in the new build-order fixture: GNU make can regenerate included makefiles even under =-n=, contaminating dependencies with a temporary output path. The fixture now includes a dry-run clean goal to suppress dependency-file inclusion without executing any clean recipe. The complete command above and a subsequent incremental build were rerun successfully after correcting the fixture.

** Sanitizers

AddressSanitizer, UndefinedBehaviorSanitizer, and LeakSanitizer pass all 241 cases in the default-backend plus Webview configuration. No sanitizer suppressions or reduced compiler warning flags were used. MCP tests and live LRG rendering are not part of this sanitizer run; MCP is covered by the full-option release suite.

#+begin_src bash
make DEBUG=1 ASAN=1 BUILDDIR=build/review-sanitize WEBVIEW=1 tests
#+end_src

LeakSanitizer could not inspect processes under the sandbox, so sanitizer execution was repeated outside it with approval. Its first unrestricted run found the test-fixture leaks listed in R33; both were corrected before the final clean run. The compiler tests now use GLib's isolated test directories so normal test runs do not populate the user's real runtime compilation cache.

* Review boundaries and dependency follow-up

The review followed terminal parsing and state transitions, PTY I/O and exit order, selection, configuration loading/saving/compilation, module lifecycle and image decoding, external pipes, optional Webview authentication/shutdown, rendering interfaces and window integration, and build/tool entry points. Renderer abstractions and module draw dispatch are exercised by tests. No live X11, Wayland, or LRG graphical session was launched, so visual behavior under an actual compositor is not claimed as verified. This is a bug-finding review, not a proof that all remaining code is defect-free.

No new dependency defect was confirmed and no dependency source was reviewed or changed. The existing [[file:known-issues.org][known-issues document]] already records graylib/raylib warnings about a duplicate object recipe, a missing function declaration, and a potentially uninitialized variable. Those existing dependency findings remain for a separate follow-up; this review linked the prebuilt graphics archives rather than investigating those sources. The previously documented GST MCP build race is fixed by R32.
